# The PARA Method — Applied

PARA is an organization scheme for a second brain that sorts everything into four categories by **how actionable it is**, not by subject. This file covers how to apply it cleanly when the simple four-line version in `SKILL.md` isn't enough.

## The four categories, in order of actionability

1. **Projects** — a series of tasks linked to a goal, with a deadline or clear finish. "Launch the new pricing page." "Plan the offsite." "Write the Q3 report." If you can picture it being *done*, it's a project.
2. **Areas** — a sphere of activity to be maintained over time, with a standard to uphold but no end state. "Health." "Finances." "Direct reports." "Home." You don't finish an area; you keep it going.
3. **Resources** — a topic or interest that may be useful in the future but isn't tied to a current project or area. "Web design inspiration." "Negotiation tactics." "Travel ideas." This is reference material and the general library.
4. **Archive** — inactive items from the other three. Completed projects, areas you no longer maintain, resources that have lost relevance. Kept for recovery, out of the way.

The ordering matters: when deciding where something goes, check from the top down. Is it for a specific active project? File it there. No? Does it support an ongoing area? There. No? It's a resource. No longer relevant at all? Archive.

## The core filing heuristic

When a note or file arrives, don't ask *"what is this about?"* Ask:

> **"Which of my active projects will this help move forward?"**

If there's a clear answer, file it under that project — even if topically it seems to belong elsewhere. A research paper about sleep that you're using for a talk on productivity belongs under the *talk* project, not under a "sleep" resource folder, because that's where you'll reach for it.

If no project fits, walk down the ladder:
- Does it support an **area** you maintain? File there.
- If not, it's a **resource** — file by topic.
- If it's not useful to any of those and won't plausibly be, consider not keeping it at all.

This top-down pass is what keeps the system action-oriented. Filing by actionability means the things you're working on now are surrounded by exactly the material that serves them.

## Why not organize by topic?

Topic-based filing ("Marketing," "Psychology," "Finance") feels logical but produces an inert library: everything has a place, but nothing is connected to what you're actually doing. You end up with a beautiful reference system you never open, because your *work* is organized by project while your *knowledge* is organized by subject, and the two never meet.

PARA closes that gap by mirroring how work actually happens — around goals and responsibilities. The payoff is that opening a project shows you everything relevant to it, gathered from across every topic.

## Notes flow between categories

The single most useful idea in PARA: **the same item moves as its relevance changes.** Nothing is filed permanently.

- A negotiation-tactics note sits in **Resources** → you get a salary review coming up → it moves to that **Project** → the review ends → it goes to **Archive**.
- An "area" can spin off a "project" (the *Health* area spawns a *Run a half-marathon* project), then fold back when done.
- An archived project's notes can be pulled back out and revived for a similar new project.

Practically, this means: don't agonize over the "correct" home for something. Put it where it's useful *now*; move it when that changes. The review rhythm (processing the inbox, opening/closing projects) is what drives this flow naturally.

## Handling the awkward cases

- **"It fits two projects."** Put it with the one it serves most, or keep it in Resources and reference it from both. Don't duplicate heavily — one canonical home, linked from elsewhere if needed.
- **"It fits nowhere."** That's usually a signal it isn't worth keeping. If you're sure it'll matter someday, drop it in Resources under the best-guess topic and move on. Don't build elaborate structure for maybes.
- **"Is this a project or an area?"** Ask whether it can be completed. A deadline and a finish line → project. Open-ended upkeep → area. "Get taxes filed" is a project; "manage finances" is the area it lives under.
- **"My Resources are a junk drawer."** Fine, as long as it's searchable. Resources is allowed to be loose — it's the low-priority library. The discipline that matters is keeping *Projects* clean and current.

## Setting PARA up from scratch

1. Make the four top-level containers (folders, or whatever the tool uses): Projects, Areas, Resources, Archive.
2. List current **projects** — the handful of things with goals and deadlines you're actively pushing on. Create one container each.
3. List ongoing **areas** of responsibility. One each.
4. Everything else that's reference-like goes to **Resources**, loosely by topic.
5. Sweep anything inactive or done into **Archive**.
6. Add a **capture inbox** — one landing spot for new notes before they're filed.

Don't migrate years of old notes up front. Set up the structure, route *new* capture through it, and pull old notes out of the archive only when a project actually needs them. The system proves itself through use, not through a big initial reorganization.

## The one rule to remember

When in doubt, file by **where you'll use it**, not by **what it's about** — and keep the structure light enough that you'll actually maintain it.
